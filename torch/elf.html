ELF 到底在做什么

ELF 把语言生成视为连续嵌入空间中的流匹配过程。它在大多数时间步上保持连续表示，仅在最后一步把嵌入投影回离散 token。这与主流离散扩散语言模型（如 MDLM、Duo）形成鲜明对照。

三个关键设计：
  • 嵌入空间去噪：使用冻结的 T5 编码器把 token 映射为连续向量 $x$，所有去噪都发生在该空间内。
  • 共享权重的去噪器与解码器：同一个网络在 $t \in [0, 1)$ 时执行去噪，在 $t = 1$ 时切换到解码模式，输出 token logits。
  • 训练时分类器无关引导：通过自条件构造引导信号，单次前向即可输出 CFG 后的速度场，避免推理时的双倍开销。

与其他方法的相对位置

方法状态空间过程每步离散化独立解码器

四个你需要先知道的概念

2.1 WHAT IS DIFFUSION

什么是 Diffusion（扩散）模型

Diffusion 起源于 2015 年（Sohl-Dickstein）和 2020 年（Ho et al., DDPM），最初是为图像生成设计的。核心想法只有三步：

  1. 正向过程：拿一张清晰图片，不断加高斯噪声，T 步之后变成纯噪声。
  2. 训练：训练一个网络，能从"当前噪声状态 + 时间步"预测出"加了多少噪声"或"原图是什么"。
  3. 反向（生成）过程：从纯噪声出发，让网络一步步去噪，T 步后得到一张清晰图。
Flow Matching 是 Diffusion 的一个变种：把"离散加噪步骤"换成"连续时间的直线插值"，本质相同 —— 学一个去噪函数。ELF 用的就是 Flow Matching 公式。
2.2 DIFFUSION vs AR

跟 GPT 一样的 AR 模型有什么不同

GPT 这类自回归 (AR) 语言模型一次生成一个 token：

"the"                    → 网络猜下一个 → "cat"
"the cat"                → 网络猜下一个 → "sat"
"the cat sat"            → 网络猜下一个 → "on"
"the cat sat on"         → 网络猜下一个 → "the"
...

每个 token 都依赖之前所有 token，方向是严格的左→右，一旦生成不可修改。生成 L 个 token 需要 L 步前向。

Diffusion 完全不同 —— 它一次性生成整个序列：

初始: [noise   noise   noise   noise   noise]    (t = 0)
       整序列同时去一次噪 ↓
       [noisy  mid     noise   mid     noisy]    (t = 0.25)
       整序列同时去一次噪 ↓
       [mid    clean   mid     clean   mid  ]    (t = 0.5)
       整序列同时去一次噪 ↓
       ...
最终: [the    cat     sat     on      the  ]    (t = 1)

整个序列同时进化。每一步网络看到整个噪声序列，对每个位置都输出一个"更接近清晰"的猜测。

核心差异速查

AR (GPT)Diffusion (ELF)
生成方向单向（左 → 右）双向 / 整体
每步代价1 个 token整序列
总步数= 序列长 L远小于 L（典型 32-64）
已生成是否可改否是（每步重新看整序列）
训练目标next-token CEdenoise MSE
典型 attentioncausalfull（双向）
AR 把"生成一段文字"分解为 L 个 next-token 决策；Diffusion 把它分解为 N 次"整序列去噪"。两种分解方式各有取舍：AR 长序列更省内存，Diffusion 短步数更并行。
2.3 WHY ATTENTION

为什么 Diffusion 还可以用 Transformer / Attention

初学者常困惑：AR 用 Transformer 是因为它能加 causal mask 适合 next-token prediction；那 Diffusion 为什么也用 Transformer？

答案：Transformer 不是"为 AR 而生"的，它本质上是一个强大的序列到序列处理器。它做的事很简单：

  • 输入一个序列 (B, L, D)
  • 输出一个等长序列 (B, L, D)
  • 序列每个位置都能 attention 到其他任意位置

AR 只是 Transformer 的一种用法：加 causal mask（只看前面的 token），再用 next-token cross-entropy 损失训练。换一种用法就是 Diffusion：

  • 输入：当前 noisy 序列 $z_t$（已经在嵌入空间）+ 时间 $t$
  • 输出：每个位置的清晰嵌入预测 $\hat x$（整序列）
  • 不需要 causal mask：所有位置可以互看 —— 这正是 Diffusion 利用双向信息的关键
  • 损失：MSE on $\hat x$（每个位置独立）
ELF 用的是没有 causal mask 的 Transformer，加上一些扩散标配（time embedding、self-conditioning、CFG token）。架构是 DiT (Diffusion Transformer) 风格，2023 年起在图像扩散里成熟，ELF 把它搬到了语言上。

这也回答了另一个常见问题："如果不是 next-token prediction，那训练目标是什么？" —— 训练目标是 regression：网络要预测干净的连续嵌入 $\hat x$，监督信号是 L2 误差。每个位置独立监督，没有"下一个 token"概念。

2.4 WHAT IS CFG

什么是 CFG（Classifier-Free Guidance）

CFG 起源于图像扩散（Ho & Salimans, 2021），是一个"让生成更贴近你想要的"的简单技巧。

原始动机：文生图

假设你训练了一个 text → image 扩散模型。给一段文字 c = "a cat playing piano"，模型应该生成猫弹钢琴的图。但有时候生成的图与文字关系不紧密（也许是只猫但没钢琴）。CFG 的诀窍：

  1. 训练时：10% 概率"丢掉" condition c（用空 prompt 代替），让模型同时学到：
    • 有条件预测 $\epsilon_\theta(z, c)$（看到 "cat playing piano"）
    • 无条件预测 $\epsilon_\theta(z, \emptyset)$（什么提示都没有）
  2. 推理时：在两个预测之间做线性外推： $$\epsilon = \epsilon_\theta(z, \emptyset) + \omega \cdot \big[\epsilon_\theta(z, c) - \epsilon_\theta(z, \emptyset)\big]$$
    • $\omega = 1$：等价于纯有条件，没有 CFG 效果
    • $\omega > 1$：朝"有条件"方向多走一些，生成更紧密匹配 c
    • $\omega < 1$：朝"无条件"方向走，更多样、更"野"

本质就是：把"条件和无条件预测的差"放大或缩小。

ELF 怎么用 CFG（没有 prompt 怎么办？）

ELF 做的是无条件语言建模（OpenWebText），并没有像文生图那样的"prompt c"。CFG 怎么用？

办法：把自条件信号 $\hat x'$ 当作 condition（§3.8 详解）：

  • 有条件: input = $[z_t, \hat x']$ → 网络看到上一步预测 → 输出 $v_\text{cond}$
  • 无条件: input = $[z_t, \mathbf{0}]$ → 网络看不到任何辅助信号 → 输出 $v_\text{uncond}$
  • CFG 公式: $v = v_\text{uncond} + \omega \cdot (v_\text{cond} - v_\text{uncond})$

ELF 还做了一步优化：把 CFG 公式烘焙进训练目标，单次前向就能直接输出 CFG 速度场，避免推理时跑两次前向。这就是为什么训练时 denoise 分支跑 4 次前向（详见 §5）。

CFG 是一个通用技巧：只要训练时有"有条件 / 无条件"两个版本的预测，推理时就能做外推。ELF 的创新是用自条件构造这个二元，让无条件语言模型也能享受 CFG。

这四个概念准备好之后，下一节我们从最底层的离散 vs 连续的尴尬出发，一步步推到 ELF 的完整框架。

2.1 THE GAP

一个尴尬的问题：离散 vs 连续

如果你见过 Stable Diffusion，你知道扩散模型在图像上工作得有多漂亮：从一团噪声出发，逐步去噪，最后变成一张清晰的画。背后的关键是图像是连续的数据 —— 每个像素的 RGB 值是 0 到 255 的实数，你可以加一点高斯噪声，也可以做线性插值。

但语言不是这样。一个 token 是一个离散的 ID：在 vocab 表里 ID 17 是 "cat"，ID 219 是 "dog"。你没法在 cat 和 dog 之间"加 50% 高斯噪声"—— 这个概念不存在。

所以问题就摆在这里：

怎么把扩散这类专为连续数据设计的方法，用到离散的语言上？
2.2 THE BRIDGE

嵌入空间：用编码器搭桥

办法是先把每个 token 通过一个编码器映射到一个连续向量。T5-small 把 "cat" 这个 ID 映射成一个 512 维的向量；把 "dog" 映射成另一个 512 维向量。现在每个 token 在 $\mathbb{R}^{512}$ 这个连续空间里都有一个具体的坐标。

更妙的是：cat 和 dog 之间的中间状态现在有意义了 —— 那也是一个 512 维向量，只是它不对应任何已知 token。在嵌入空间里做"加 50% cat 50% dog"完全合法。

ELF 用的是冻结的 T5-small：训练 ELF 的过程中，T5 参数永远不变。每次需要把 token 转成向量时调用一次就行。

Latent Diffusion Models（也就是 Stable Diffusion 的骨架）用了同样的桥梁思路 —— 它们用 VAE 把 512×512 像素压缩成 64×64×4 的潜在码，再在这个潜在空间里做扩散。ELF 把这个思路搬到语言上：T5 编码器 ≈ VAE encoder。区别是 LDM 还需要一个独立的 VAE decoder 才能从潜在码回到像素，而 ELF 不需要 —— 下文 §2.8 会讲它怎么做到的。
2.3 THE FIELD

流场：箭头指向数据

站到嵌入空间里。想象它是一个 2D 平面（真实是 512D，但 2D 更容易画）。平面上散落着许多数据点 —— 这些是真实文本对应的嵌入 $x_1, x_2, \ldots$

我们想做的事情：从一个随机噪声点出发，走到某个数据点附近。

办法是在平面的每一个位置都定义一个"流速向量" $v(z, t)$，它告诉你"站在这里、这个时刻，下一步该往哪走"。这一整张箭头图，就叫做流场 (vector field)。

沿着流场里的箭头一步一步走，无论从哪起步，最终都会被冲到数据点附近。这就是流的工作原理。

想象一条河流：河床里散落着鹅卵石（数据点）。河水（流场）总体向下游流，但在每个位置因为河床形状不同而方向略有偏转。一颗树叶（采样起点）扔进河里，会被水流带着走，最后停在某颗鹅卵石附近。流场学习的就是这条"河水"。
训练的目标，就是让神经网络学会这张流场图：给定任意位置 $z$ 和时刻 $t$，预测流速 $v_\theta(z, t)$。
2.4 THE RECIPE

直线插值：最朴素的训练样本

训练样本怎么造？最简单的办法：对每对 (噪声 $\epsilon$, 数据 $x$)，画一条直线连接它们。沿着这条直线走，每一步速度都一样：$v = x - \epsilon$（终点减起点，常数）。

把这条直线参数化：

rectified flow · 直来直去的流
$$z_t = t \cdot x + (1 - t) \cdot \epsilon, \quad t \in [0, 1]$$
$t = 0$ 时 $z = \epsilon$（噪声端）； $t = 1$ 时 $z = x$（数据端）； 中间任意 $t$ 都是 $\epsilon$ 和 $x$ 的加权平均。

这种最朴素的"两点连线"叫做 rectified flow。"rectified" 是"已经拉直"的意思 —— 跟有些方法用曲线连接不同，这里用最简单的直线。

2.5 THE AVERAGE

一万条直线：网络学的是"平均速度"

现实中我们有很多对 $(\epsilon_i, x_i)$ 配对，每对一条直线。这些直线在空间中互相穿插，乱成一团。

考虑某个具体位置 $z$。可能有多条直线穿过它：对应不同的时间 $t$、对应不同的 $(\epsilon, x)$ 配对。每条线在 $z$ 处给出一个不同的速度 $v$。

这就需要做一件事：把所有穿过 $z$ 的速度"平均"起来。更精确地，神经网络学的是条件期望：

conditional expectation · 网络真正逼近的量
$$v_\theta(z, t) \;\approx\; \mathbb{E}\big[\, x - \epsilon \;\big|\; z_t = z,\; t \,\big]$$
"在位置 z、时刻 t，平均而言流速指向哪里？"

这个条件期望就是真正的"全局流场"。神经网络的工作，就是用 N 条直线训练数据，逼近这个全局流场。沿着这个学到的流场，从任意噪声出发都能到达数据分布上的某个点。

Flow Matching 的精髓：用大量 (ε, x) 配对的直线数据，训练网络逼近条件期望 $\mathbb{E}[v | z, t]$。这个逼近本身就是一个全局流场。
2.6 THE TARGET

预测 x，而不是预测 v

理论上让网络直接输出 $v$ 就够了。但实践中 ELF 让网络输出干净嵌入 $\hat x$，再从 $\hat x$ 反推速度：

x-prediction · 等价但更稳定
$$\hat v = \frac{\hat x - z_t}{1 - t}$$

为什么这样更稳？论文 Sec. C.1 在 512、768、1024 维三档上对比，x-prediction 显著优于 v-prediction 和 ε-prediction。直觉是：

  • 高维数据通常集中在一个低维流形上（流形假设）。语言嵌入也是 —— ℝ^512 里只有很小一部分点对应"真实文本"。
  • 让网络预测 $x$ 等价于让它学会"把当前点投影到流形"。这是个具体的、有几何意义的任务。
  • 让网络预测 $v$ 在远离流形时方向感很弱 —— $v$ 是个向量场量，没有"哪个 v 才合理"的天然先验。

损失就是 L2 误差：

denoise loss · MSE on clean embedding
$$L_\text{MSE} = \mathbb{E}_{t, x, \epsilon}\left[\frac{1}{(1-t)^2} \|\hat x_\theta(z_t, t) - x\|^2\right]$$
等价于 $\|\hat v - v\|^2$，因为 $\hat v - v = (\hat x - x) / (1-t)$。
2.7 THE WALK

反向：从噪声漂到数据

训练完了，怎么用？给一个新的随机噪声 $\epsilon$，要把它变成一个清晰嵌入 $x$。

z_0 ← 一个新随机噪声 ε ~ N(0, I)

for i in 0, 1, …, N-1:
    x_pred = ELF(z_i, t_i, mode="denoise")      # 问网络：清晰版长什么样？
    v_pred = (x_pred - z_i) / (1 - t_i)          # 反推速度
    z_{i+1} = z_i + Δt · v_pred                  # 沿速度走一小步

# 走完 N 步，z_N 就是一个清晰嵌入 ≈ 某个 x

每一步在做三件事：

  1. 问网络："站在 $z_i$ 这个位置、$t_i$ 这个时刻，你猜清晰版的 $x$ 应该是什么？"
  2. 反推速度：从 $\hat x$ 和当前 $z$、$t$ 反算出这一步该往哪走。
  3. 走一小步：沿 $v_\text{pred}$ 走 $\Delta t$ 那么远。

$N$ 步之后，从纯噪声漂到了一个清晰嵌入。论文的最佳配置是 32 步（SDE 采样器）或 64 步（ODE 采样器）—— 比离散 DLM 动辄 1024 步要少得多。

2.8 SELF-CONDITIONING

让模型看到它自己上一步的猜测

回看 §2.7 的采样循环 —— 它有个隐藏的浪费：

for i in 0 .. N-1:
    x_pred = ELF(z_i, t_i)           # 网络只看到 z_i 和 t_i
    v_pred = (x_pred - z_i) / (1-t_i)
    z_{i+1} = z_i + Δt · v_pred

每一步网络只看见当前位置 $z_i$ 和当前时间 $t_i$。它不知道上一步它自己预测过什么。每一步都是从零开始猜。

Self-conditioning（Chen et al., "Analog Bits"）的想法极简：把上一步的预测 $\hat x'$ 作为额外输入喂给网络，告诉它"上次我猜的是这个，你看看现在要不要修正"。

x_prev = 0                                # 初始没有"上次"
for i in 0 .. N-1:
    x_pred = ELF(z_i, t_i, x_prev)        # ← 多了一个输入
    v_pred = (x_pred - z_i) / (1-t_i)
    z_{i+1} = z_i + Δt · v_pred
    x_prev = x_pred                        # 留给下一步

实现：通道拼接 + 投影

"多一个输入"在代码里就是通道维度上的 concat：

self-cond input transformation
$$\text{input} = \big[z_t,\; \hat x'\big] \in \mathbb{R}^{L \times 2C} \;\xrightarrow{\;\text{SelfCondProj}\;}\; \mathbb{R}^{L \times C}$$
两路嵌入沿通道拼接，再用一个线性层投影回原通道数。SelfCondProj 是网络里的一层 nn.Linear(2C, C)。

训练时怎么造 $\hat x'$？

采样时 $\hat x'$ 是"真实的上一步预测"，但训练时根本没有"上一步"—— 训练样本是 (x, ε, t) 三元组，是平行采的。怎么模拟？

论文的做法分两半：

  • 50% 的样本：用零向量代替 $\hat x'$，即 input = $[z_t, \mathbf{0}]$。模型学会"在没有自条件时也能工作"，因为采样的第一步也确实没有"上一步"。
  • 另 50% 的样本：先做一次额外的前向得到一个 $\hat x'$（截断梯度），再用 input = $[z_t, \text{sg}(\hat x')]$ 做训练前向。模型学会"利用上一步的预测"。

这就是为什么 denoise 分支训练时至少要跑 2 次前向。加上 §2.x 会讲的 CFG（也是用 self-cond 的输出作为引导信号），一共要跑 4 次。

训练时的 4 次前向（§5 详解）来源就在这里 —— self-conditioning 必须先有一次"无条件"前向，才能拿到 $\hat x'$ 去做"有条件"前向；CFG 又需要 cond / uncond 各一对。

为什么有用？两个直觉

  1. 给采样轨迹一个"出发点"。每一步只需做"小修正"而非"全猜"，误差不易爆炸。
  2. 跨时间步的信息传递。早期一个不太准的预测，可以在后期被自条件链拉回正确轨道，相当于隐式的"迭代精化"。

与 CFG 的联系

self-cond 的 $\hat x'$ 还有一个更深的作用：它是 ELF 做 CFG（分类器无关引导）的"条件信号 c"。

  • "有条件"分支：input = $[z_t, \hat x']$ → 网络得到 $v_\text{cond}$
  • "无条件"分支：input = $[z_t, \mathbf{0}]$ → 网络得到 $v_\text{uncond}$
  • CFG 外推：$v = v_\text{uncond} + \omega (v_\text{cond} - v_\text{uncond})$

这就是 §4 那 4 次前向的逻辑根源。下一节 §2.9 先回到 decode mode，然后 §3-5 详解训练循环和 CFG。

2.9 THE LAST STEP

最后一步：从嵌入回到 token

到这里我们得到了一个 512 维向量 $z_N \approx x$。但我们要的是 token，不是向量。

不同方法在这里分道扬镳：

  • LD4LG / Cosmos 等 latent diffusion 方法：单独训练一个 decoder（通常是另一个 transformer），把 $z_N$ 映射回 token。多一个模型 + 多一份训练成本。
  • ELF：让同一个网络在 $t = 1$ 时切换到 "decode 模式"，直接输出 token logits。零额外模型。

ELF 的实现是这样的：

decode mode · @ t = 1
$$\text{logits} \;=\; W \cdot \text{ELF}(z_N,\; t=1,\; \text{mode}=\text{decode})$$ $$\text{tokens} \;=\; \arg\max(\text{logits})$$
$W$ 是一个可学习的 "unembed" 矩阵，把 ℝ^512 投影到 vocab 大小（~50K）的 logit。

这个 decode 模式怎么训练？训练时随机选 20% 的样本走 decode 分支：

  • 输入：$\tilde z = \lambda \cdot x + (1-\lambda) \cdot \epsilon \cdot s_\text{dec}$，其中 $\lambda$ 是 per-token 采的逻辑正态噪声（每个 token 独立采，不同于 denoise 分支的整序列共用一个 $t$）。这样得到的 $\tilde z$ 是 $x$ 的"弱扰动版"。
  • 监督：交叉熵 $L_\text{CE}(W \hat x, s)$，迫使网络从弱扰动中恢复原 token。
  • mode token：在序列前 prepend 一个可学习的 "mode 标识 token"，告诉网络"现在是 decode 模式，请输出 token logits 而不是干净嵌入"。
为什么共享权重的解码器行得通？因为 denoise 分支后期（$t \to 1$）网络看到的 $z_t$ 已经非常接近 $x$；而 decode 分支看到的 $\tilde z$ 也是 $x$ 的弱扰动。两者的输入分布相似，所以同一个网络能同时学好两件事。论文 Sec. 4.1 (Fig. 5b) 在共享 vs 独立 decoder 上做了对比，共享反而更优。
2.10 PUTTING IT TOGETHER

把它拼回去

到这里你已经掌握了 ELF 的完整故事。复述一遍：

  1. 用冻结的 T5 编码器把 token 映射到 ℝ^512 的连续嵌入空间 (§2.2)。
  2. 在这个空间里，定义一个流场：每个位置都有一个流速向量指向数据 (§2.3)。
  3. 用大量 (ε, x) 直线插值样本训练一个神经网络逼近这个流场的条件期望 (§2.4–2.5)。
  4. 让网络预测干净嵌入 $\hat x$（不是 v），损失是 MSE (§2.6)。
  5. 采样时从噪声出发走 N 步，每步问网络"清晰版是什么"再沿速度走一小段 (§2.7)。
  6. 每一步的预测作为自条件信号传给下一步，让模型"修正"而非"重猜" (§2.8)。
  7. 最后一步切换到 decode 模式，让同一个网络输出 token logits，argmax 拿到 token (§2.9)。

剩下还要解决三件事，下面几节专门讲：

  • 训练时 CFG（§4–5）：怎么把自条件信号变成质量引导，让生成更"像真实文本"。
  • 采样器细节（§6）：ODE 和 SDE 两种走法的区别。
  • 网络架构（§7）：DiT 的具体堆叠方式，三类控制 token 怎么 inject。

然后是工程实现 —— §8 是文件级代码导览，§9 是 H200 训练的具体注意事项。

训练流程

论文图 9 把训练分成两条分支：denoise 分支（概率 $1 - p_\text{dec}$，常用 0.8）执行 MSE 训练，decode 分支（概率 $p_\text{dec}$，常用 0.2）执行 CE 训练。两条分支共享同一套权重，由前缀 mode token 区分。

分支决策与 DDP 同步：每个 micro-batch 在 rank 0 上做一次伯努利采样，再用 dist.broadcast 同步到所有 rank。否则不同 rank 走不同分支，DDP 的梯度桶会因为参数集合不同而 hang 住。详见 train.py::broadcast_branch。

自条件与训练时 CFG

denoise 分支单次训练实际跑了 4 次前向。理解它是读懂 train_step.py 的关键。下面这个步进播放器可以按节奏过一遍。

实现位置

  • 整体编排：torch/train_step.py::_denoiser_branch
  • 采样侧的 CFG（推理时）：torch/utils/sampling_utils.py::_forward_sample 和 _forward_sample_self_cond
  • $\omega$ 的对数均匀采样：sample_cfg_scale（在 $[1+\omega_\min, 1+\omega_\max]$ 上对数均匀，再减 1）
容易出错的细节：
  • 第 ① 次和第 ③ 次在确定性模式下数学上等价（都是 $[z, 0]$，模型设为 eval）。复用可节省约 25% 训练算力，但 PyTorch 实现按论文原版分开做，便于与 JAX 实现逐行对照。
  • $v_\text{target}$ 必须 detach()。否则反向会试图穿过第 ③ ④ 次前向，OOM 几乎必然。
  • $\omega = 1$ 时 $1 - 1/\omega = 0$，CFG 项消失；与无 CFG 训练数学等价。

采样过程 · ODE / SDE

采样从 $z_0 \sim \mathcal{N}(0, I)$ 开始，沿着学习到的速度场积分。前 $N{-}1$ 步可用 ODE 或 SDE 更新，最后一步固定切换到 decode 模式直接读出 token。

ODE vs SDE · 两种步长更新

采样器更新公式特点
ODE (Euler) $z_{t+\Delta t} = z_t + \Delta t \cdot v_\theta(z_t)$ 确定性；步数少时容易积累误差
SDE-inspired $\alpha = 1 - \gamma \Delta t$
$t_\text{back} = \alpha t,\ z_\text{back} = \alpha z + (1-\alpha)\epsilon$
$z_{t+\Delta t} = z_\text{back} + (t_\text{next} - t_\text{back}) v_\theta(z_\text{back})$ 		每步注入噪声再前进一小段；$\gamma$ 越大噪声越强；少步数下显著更好

  • 整段循环：torch/utils/generation_utils.py::run_sampling_single_batch
  • 最终解码：torch/utils/generation_utils.py::decode_batch
  • 时间网格：torch/utils/sampling_utils.py::get_sampling_steps

网络架构 · DiT-style

ELF 沿用 Diffusion Transformer 设计：RMSNorm + RoPE + SwiGLU + qk-norm，主体外加三类"控制 token"（time / CFG ω / mode），通过 in-context 方式注入条件而非 adaLN-Zero。论文 Sec. C.4 比较表明 in-context 与 adaLN-Zero 性能相近但参数从 148M 降到 105M。

关键工程要点 · 8 × H200

分布式 · 纯 DDP，无需 FSDP

ELF-L 652 M 参数 × fp32 ≈ 2.6 GB；加上 AdamW 状态约 7-8 GB；单卡 H200 拥有 141 GB HBM，DDP 足矣。激活内存才是大头，必要时启用 activation checkpointing（M 与 L 默认开启）。

混合精度策略

权重与梯度保持 fp32，仅前向用 bf16 autocast。 原因：DDP 的 ring all-reduce 在 fp32 下是 bit-identical 的，否则 Muon 的 Newton-Schulz 迭代会在不同 rank 上产生微小差异，无法保证参数同步。

Muon 优化器在 DDP 下的正确性

Muon 对 2D 矩阵参数做 NS 正交化。我们的策略是：

  • 梯度保持 fp32，每个 rank 拿到 bit-identical 的全局梯度
  • 每个 rank 独立运行 NS 迭代，自然得到 bit-identical 的更新
  • 嵌入层、bias、norm 标量、unembed 头、time MLP 等参数走 AdamW
  • 52 个 2D 张量（86 M numel）走 Muon；115 个非 2D 张量（18.6 M numel）走 AdamW，总和正好 105 M

分支决策必须 rank-broadcast

每个 micro-batch 一次伯努利采样决定走 denoise 还是 decode 分支。必须在 rank 0 上采样后广播到所有 rank。否则有的 rank 跑 4 次前向、有的跑 1 次，DDP 在解码头参数（仅 decode 分支用到）的梯度桶处直接 hang。

EMA 仅在 optimizer step 时更新

梯度累积时只在 (step + 1) % grad_accum_steps == 0 的边界更新 EMA。否则有效 decay 退化为 $\text{decay}^K$，K 越大偏离越严重。

T5 编码器的 3D mask 兼容性

HF transformers 较新版本对 3D 形状的 attention mask 处理路径变化频繁。本实现把 3D keep-mask 主动转为 4D additive mask（$(B, 1, L, L)$，值为 0 / $-\infty$）后传入，绕过 masking_utils 的不稳定路径。

损失掩码的安全除法

条件 token、padding token 不参与损失，但不能让它们因为 0 / 0 产生 NaN：

safe = torch.where(loss_mask > 0, per_token_loss, 0)
loss = (safe * loss_mask).sum() / loss_mask.sum().clamp(min=1.0)

CFG scale 的对数均匀采样

在 $[1 + \omega_\min, 1 + \omega_\max]$ 上对数均匀采样后减 1，得到偏小值的分布。这是论文继承自图像扩散 CFG 的做法，并非 $[\omega_\min, \omega_\max]$ 上直接对数均匀。
