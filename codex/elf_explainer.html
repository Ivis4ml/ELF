§ 1

为什么要把语言生成 从离散搬到连续？

语言天然离散：一个位置上要么是 "the"，要么是 "a"，没有中间状态。 扩散模型天然连续：它要在每一步把噪声修正一点点。两者放一起，问题就来了。

过去十年的大语言模型几乎清一色是自回归（autoregressive, AR）：从左到右一个 token 一个 token 地预测。 GPT、Llama、Qwen 都是这个范式。它的优点是训练目标干净 （p(x_t | x_{<t}) 的交叉熵），缺点也很明显：

  • 串行生成。生成第 N 个 token 必须先有前 N-1 个，整段文本无法并行采样。
  • 误差累积。前面采错了，后面没机会回头改。
  • 难以编辑。中间插入或重写一句话，整个上下文都要重新评估。

扩散模型在图像上已经验证：从一个噪声分布出发，反复降噪，最终得到一张图。这给语言生成提供了第二条路： 并行采样，可迭代修正，并且天然支持 classifier-free guidance（CFG）。 问题是怎么把"离散 token 上的扩散"变成"连续状态上的扩散"。这正是 ELF 要解决的问题。

ELF 的核心主张

不要在离散 token 上做扩散，也不要训一个独立的 latent decoder。直接用冻结的预训练 encoder （这里是 T5-small）把 token 序列映成连续嵌入 x，扩散就在这个嵌入空间里发生。 到最后一步 t=1，同一个 Transformer 切换 mode token，把连续嵌入"翻译"回离散 token。 一个网络，两个目标（denoise + decode），共享权重。

一句话总结
ELF = Flow Matching on T5 embeddings + 共享 denoise/decode 主干 + token 级控制信号注入。 训练目标是 velocity MSE（80%）加 token 交叉熵（20%）的混合。

§ 2

三种语言生成范式：AR、离散扩散、连续扩散

在跳进 ELF 之前，先看清楚自回归（AR）、离散扩散（D3PM 系）和连续扩散（ELF 所属）在生成结构上到底差在哪里。 这张对比图是后面所有数学的直觉来源。

A · Autoregressive

长处与短板

长：训练目标干净，KV cache 推理高效。
短：串行生成、长程一致性差、无法回头改。

目标 \[ p(\x) \;=\; \textstyle\prod\nolimits_t\, p\!\left(x_t \mid x_{\lt t}\right) \]
B · Discrete Diffusion

D3PM / MaskGIT 系

在 token 类别空间上做马尔可夫破坏与恢复。 问题：词表很大（数万到十万），转移矩阵不容易设计；目标仍是分类目标，难以借力 Flow Matching 的连续优化。

目标 \[ p(x_{t-1} \mid x_t),\; \text{类别分布} \]
C · Continuous (ELF)

本仓库实现

用 T5 encoder 把 token 投到稠密向量，去噪和回 token 都共享一个 Transformer， 训练用 Flow Matching velocity MSE，最后一步用 unembedding 头做分类。

目标 \[ 0.8 \,\big\|\v_{\text{pred}} - \v_{\text{target}}\big\|^2 + 0.2\,\mathrm{CE}(\mathrm{unembed}) \]
为什么 ELF 不在 token 上做扩散？
类别空间是离散的，velocity 不可定义。 Flow Matching 需要在每一点 $(x_t, t)$ 上算速度场 $v(x_t, t)$，但 token id 是整数，无法做线性插值。 把 token 嵌成连续向量后，速度场就有了几何意义——它指向"如何把噪声修正成干净嵌入"的方向。
§ 3

Flow Matching：从噪声到数据的一条直线

ELF 用的 Flow Matching 是 Lipman et al. (2023) 的 rectified flow 变体。 核心思想：人为指定一条从噪声 ε 到数据 x 的概率路径，让网络去拟合"沿这条路径前进的速度"。

3.1 直觉：每个数据点都来自一条直线

从一个随机噪声 ε ∼ 𝒩(0, I) 出发，到达数据点 x。 我们可以画无数条路径连接它们——曲线、折线、螺旋都行。 Flow Matching 选择最简单的一条：直线。

定义中间状态 z_t 沿这条直线插值：

概率路径 · linear interpolation 3.1 \[ \z_t \;=\; t\,\x \;+\; (1-t)\,\eps, \qquad t \in [0, 1] \]
两端条件：$\z_0 = \eps$（纯噪声），$\z_1 = \x$（干净数据）。中间任何一点 $\z_t$ 都是噪声和数据的凸组合。

既然路径是直线，速度就是常数——对 $t$ 求一阶导跟 $t$ 无关：

瞬时速度 · 沿线性路径 3.2 \[ \v(\z_t, t) \;=\; \frac{d\z_t}{dt} \;=\; \x - \eps \]
这是这条特定线性路径的速度，不是网络的输出。训练时 $\x$（T5 嵌入）与 $\eps$（采样的高斯噪声）都已知，所以 $\v_{\text{target}}$ 是已知真值。
关键观察
训练时 x 和 ε 我们都知道（x 是 T5 嵌入，ε 是采样的高斯噪声），所以 v_target = x − ε 是已知的真值。 推理时，给定 z_t 和 t，我们要让网络反推出这个速度，然后用 ODE 沿着速度场走到 z_1。

3.2 把 v-pred 换成 x-pred：ELF 的选择

上面式子里网络应该直接预测速度 v。但 ELF 采用一个等价的变量替换：让网络预测干净数据 x̂，再从中算出速度。 原因有三个：

  • 稳定性。x 的尺度在训练中近似恒定（T5 嵌入归一化过），而 v 的尺度随 (x, ε) 组合波动较大。
  • 解释性。x̂ 本身就是网络对"这段嵌入想表达什么"的当前猜测，可以直接做 self-conditioning（§6）。
  • 解码兼容。同一个 x̂ 在 t=1 时就是 unembedding 的输入，denoiser 和 decoder 共享权重因此天然可行。
x-pred → v-pred 换算 3.3 \[ \v_{\text{pred}} \;=\; \frac{\hatx - \z_t}{\max(1 - t,\; \epsilon_t)} \]
推导：把 $\z_t = t\,\x + (1-t)\,\eps$ 对 $\eps$ 求逆，得 $\eps = (\z_t - t\,\x)/(1-t)$。 代回 $\v = \x - \eps$ 并整理（用 $\hatx$ 替换 $\x$）即得。分母里的 $\epsilon_t$ 是数值下限（默认 $10^{-3}$），防止 $t\to 1$ 时除零。

3.3 训练损失：MSE on velocity

denoiser 训练损失 3.4 \[ \L_{\text{denoise}} \;=\; \E_{t,\,\x,\,\eps}\, \Big\| \v_{\text{pred}}(\z_t, t) \;-\; \v_{\text{target}} \Big\|^2 \]
其中 $\z_t = t\,\x + (1-t)\,\eps$，   $\v_{\text{target}} = \x - \eps$，   $\v_{\text{pred}} = \big(\mathrm{ELF}(\z_t, t) - \z_t\big) \big/ (1 - t)$。

对应 PyTorch 代码（位置：codex/elf_pytorch/training.py）

# 简化示意，实际还有 self-cond + CFG 的分支（§6/§7）
def denoise_loss(model, x, eps):
    t   = torch.rand(x.shape[0], device=x.device)        # 均匀采样 t ∈ [0, 1]
    t_  = t.view(-1, 1, 1)                                  # 广播到 (B, L, D)
    z_t = t_ * x + (1.0 - t_) * eps                       # 线性插值
    v_tg = x - eps                                          # 目标速度（常数）

    x_hat = model(z_t, t, mode="denoise")                  # 网络输出 x̂
    v_pred = (x_hat - z_t) / (1.0 - t_).clamp(min=1e-3)
    return ((v_pred - v_tg) ** 2).mean()
为什么不是 ε-pred？
经典 DDPM 让网络预测噪声 $\eps$。Flow Matching 文献证明，x-pred、v-pred、ε-pred 在线性路径下数学等价，只是把同一个未知量换了变量： \[ \hatx \;\leftrightarrow\; \v \;\leftrightarrow\; \hat{\eps} \quad \text{via} \quad \z_t = t\,\x + (1-t)\,\eps,\;\; \v = \x - \eps \] 但实现上 ELF 选 x-pred 是因为：(i) $\hatx$ 直接对应解码目标，与 §6 自条件、§7 CFG 单前向都更顺；(ii) 训练时 $\hatx$ 的尺度近似恒定（归一化过的 T5 嵌入），而 $\v$ 的尺度随 $(\x, \eps)$ 组合波动。

3.4 速度场可视化

把每个 $(z, t)$ 看作一个点，速度场 $\v(z, t)$ 就是这点上的一支箭头。 训练好的网络给出的是这个箭头场的近似；采样就是让一团粒子顺着这些箭头从噪声漂流到数据流形。

3.5 从训练目标到采样器

训练完成后，网络给出 $\v_{\text{pred}}(\z_t, t)$。生成过程就是解一个 ODE：

生成 ODE 3.5 \[ \frac{d \z_t}{dt} \;=\; \v_{\text{pred}}(\z_t, t), \qquad \z_0 = \eps \sim \N(\mathbf{0}, \mathbf{I}) \]
最简单的离散化是 Euler 法：$\z_{t+\Delta t} = \z_t + \Delta t \cdot \v_{\text{pred}}$。 ELF 默认 $N=16$ 步，质量已经接近 $N=64$；详见 §11。
§ 4

嵌入桥：冻结的 T5 把 token 投到连续向量

ELF 想在连续空间扩散，前提是要有一个稠密的"语言空间"。直接训一个 latent encoder 风险大、成本高； 冻结一个预训练 encoder 几乎不花成本就拿到了 contextualized embedding。

4.1 为什么用 T5？为什么冻结？

  • contextualized。"bank" 在不同句子里的 T5 嵌入不同，比静态 word embedding 信息密度大得多。
  • encoder-only。我们只要前向，不要解码端的 KV cache，T5 的 encoder 部分干净独立。
  • 规模适中。T5-small 60M 参数，几乎不占显存预算，可以全程跑 bf16。
  • 冻结的理由。如果让 T5 跟 ELF 一起训，目标函数会拉着它走，embedding 空间漂移会让 unembedding 头也跟着漂；冻结 = 锚住语义空间。

4.2 归一化为什么必要？

Flow Matching 假设噪声 ε ∼ 𝒩(0, I)。如果不归一化 T5 嵌入，x 的尺度（可能 2~5）跟 ε 的尺度（≈1）严重不匹配， 插值 z_t = t·x + (1-t)·ε 在 t 中段会被 x 那一项主导，网络很难学到稳定的速度场。

归一化方法：在一份验证集上算每一维的 mean μ 和 std σ，训练时全部样本做 (x − μ) / σ， 采样得到 x̂ 后做 x̂ · σ + μ 还原回原 T5 空间，再用 unembedding 头解码。 这套常数 (μ, σ) 跟 ELF 主网一起存进 checkpoint，避免推理时漂移。

§ 5

训练：两个分支，共享主干，4-pass denoiser

每个 micro-batch 抛硬币：80% 概率走 denoiser 分支，20% 概率走 decoder 分支。denoiser 分支内部又有 4 次前向， 用来同时算自条件初值、训练 forward、CFG 无条件、CFG 条件四个目标。

5.1 顶层：80/20 分支抽样

为什么不是各占 50%？因为 denoiser 是主要负担——它要学会从噪声一步步还原到干净嵌入，覆盖整段 t ∈ [0, 1]； decoder 只是在 t=1 时把嵌入翻译回 token，目标简单。论文实验把 denoiser 比例从 50% 一路调到 90%， 发现 80% 最稳。

DDP 里的陷阱
分支抉择必须所有 rank 同步。 如果 rank 0 走 denoiser、rank 1 走 decoder， DDP 的 all-reduce 会把两个目标的梯度混在一起，模型直接发散。 实现上：在每个 gradient accumulation 窗口的第一个 step 上由 rank 0 决定分支，再 broadcast 给其他 rank。 
# codex/elf_pytorch/train.py — 训练主循环窗口级分支
if step_in_epoch % grad_accum == 0:
    current_branch = broadcast_branch(
        config.decoder_prob,    # 0.2
        device,
        branch_gen,             # 仅 rank 0 持有的 Generator
    )
# 此后 grad_accum 个 micro-batch 都走 current_branch

5.2 Denoiser 分支：四次前向

denoiser 分支的一次"训练 step"实际上做了四次前向，分别对应：(a) 自条件 stop-grad 初始化、 (b) 训练真正的反向 forward、(c) CFG 无条件分支、(d) CFG 条件分支。 这四次前向只共享一个 self-attention 主干网络，输入不同的控制 token。

5.3 Decoder 分支：让同一网络学会回到 token

decoder 分支只占 20%，目标是教网络在 t=1 时把（接近干净的）嵌入翻译回离散 token。它有几个关键设计：

  • 仍然加噪。直接用干净 x 训练 decoder，模型会学不到对小扰动的鲁棒性；采样时只要噪声没消干净就崩。 所以用 z = p·x + (1-p)·ε，其中 p ∼ U(p_min, 1)，p_min ≈ 0.85——即在 t=1 附近但留点扰动。
  • mode token 切换。前缀里有 4 个 decode mode token；同样的主干网读到这些 token 就知道现在做的是分类而非速度回归。
  • 损失是 CE。把网络输出 x̂ 经 unembedding 头变成 logits，对原始 token 做交叉熵。
decoder 训练损失 5.1 \[\begin{aligned} p &\sim \mathcal{U}(p_{\min},\, 1), \qquad p_{\min} \approx 0.85 \\ \z &= p \cdot \x + (1 - p) \cdot \eps \\ \hatx &= \mathrm{ELF}(\z, \,t{=}1, \,\text{mode}{=}\text{decode}) \\ \L_{\text{decode}} &= -\sum_{i,\ell} \log \mathrm{softmax}\big(W_{\text{emb}}^{\top} \hatx_i\big)_{\ell_i} \end{aligned}\]
$p$ 从 $[p_{\min}, 1]$ 均匀抽样：$p$ 越接近 1，输入 $\z$ 越干净；下界 $p_{\min}\approx 0.85$ 提供一点扰动，让 decoder 对采样末段不完美的 $\z$ 也鲁棒。$W_{\text{emb}}$ 是 T5 词嵌入矩阵，unembed 头权重与之绑定。 
# codex/elf_pytorch/training.py · decoder 分支
def decoder_loss(model, x, tokens, eps, p_min=0.85):
    p  = torch.rand(x.shape[0], device=x.device) * (1.0 - p_min) + p_min
    p_ = p.view(-1, 1, 1)
    z  = p_ * x + (1.0 - p_) * eps
    t1 = torch.ones(x.shape[0], device=x.device)
    x_hat  = model(z, t1, mode="decode")
    logits = model.unembed(x_hat)
    return F.cross_entropy(logits.flatten(0, 1), tokens.flatten())

5.4 合并：训练主循环骨架

# codex/elf_pytorch/train.py（简化版）
for epoch in range(epochs):
    for step_in_epoch, batch in enumerate(loader):
        # --- 1. 窗口级分支抉择 ---
        if step_in_epoch % grad_accum == 0:
            branch = broadcast_branch(cfg.decoder_prob, device, branch_gen)

        # --- 2. 加载嵌入 (T5 已冻结，no_grad) ---
        x      = (batch.x - latent_mean) / latent_std
        eps    = torch.randn_like(x)

        # --- 3. 跑对应分支 ---
        with ddp_no_sync_or_sync(model, step_in_epoch, grad_accum):
            if branch == "denoise":
                loss = denoise_loss_4pass(model, x, eps, batch.cond, batch.masks, cfg)
            else:
                loss = decoder_loss(model, x, batch.tokens, eps)
            (loss / grad_accum).backward()

        # --- 4. accumulation 满则 step ---
        if (step_in_epoch + 1) % grad_accum == 0:
            torch.nn.utils.clip_grad_norm_(model.parameters(), 1.0)
            opt_muon.step(); opt_muon.zero_grad(set_to_none=True)
            opt_adamw.step(); opt_adamw.zero_grad(set_to_none=True)
            ema.update()
为什么 EMA 只在 optimizer step 上更新？
梯度累积窗口里前 N-1 个 micro-batch 不更新参数，最后一个才真正 step。 如果 EMA 在每个 micro-batch 都跑，权重会重复"看到"未更新的快照， EMA 系数实际等效于变小，跟设置的 0.9999 不符。绑定到 optimizer step 才一致。
§ 6

自条件 (self-conditioning)：把上一步的猜测喂给当前步

扩散采样是一步步降噪，每一步网络的输出 x̂ 其实是对"干净嵌入"的当前猜测。 自条件 = 把这个 x̂ 当作辅助输入塞回去，让网络下一步可以参考。它显著降低了采样所需步数。

6.1 来历：Analog Bits & Chen et al. 2023

自条件最早出现在 Chen et al. Analog Bits（2023）。观察：DDPM 训练时只看 z_t，看不到自己之前的预测。 采样时却是串行使用之前的预测，训练-推理分布不一致。 自条件就是把这个不一致补回训练中：训练时也让模型偶尔看到自己上一步的输出 x̂′。

6.2 实现：50% 概率传 x̂′，50% 概率传 0

如果总是传 x̂′，网络可能学会"复制粘贴"，不再学真正的速度场。所以采样器要做两种情况都见过：

  • 50% 用真实 x̂′（detach 后），模拟采样时"接上一步"。
  • 50% 用全零，模拟采样的第一步（还没有上一步）。

x̂′ 通过 self_cond_proj（一个 Linear(2d → d)，model.py:288）跟 z_t concat 后投影回 d 维。 初始化时 self_cond_proj 的权重对 prev 那一半设为 0，等价于"自条件刚开始时跟没有等价"，训练逐步学会怎么利用它。

§ 7

Classifier-Free Guidance：把条件信号放大 ω 倍

CFG 是 diffusion 模型最常用的"温度旋钮"：通过加权"条件 vs 无条件"的差异，控制采样向条件靠拢的程度。 ELF 的关键创新是把 CFG 预先编进训练目标，推理时不再需要双前向。

7.1 经典 CFG（推理时）

原版 CFG（Ho & Salimans 2022）每一步采样跑两次前向：一次给条件 c，一次给 ∅， 然后线性外推：

推理时合成速度 (classic CFG) 7.1 \[ \v_{\text{guided}} \;=\; \v_{\text{uncond}} \;+\; \omega \cdot \big( \v_{\text{cond}} - \v_{\text{uncond}} \big) \]
$\omega > 1$ 把"条件 vs 无条件"的差异放大，让采样更听话；$\omega = 1$ 退化为普通条件采样；$\omega = 0$ 退化为无条件采样。代价是每步两次前向。

缺点：每步两次前向，推理慢一倍。如果再叠加自条件、长序列，开销翻倍累计。

7.2 ELF 的训练时 CFG：单前向

ELF 反向用：训练时跑额外的 Pass③④ 算出 v_uncond / v_cond，把差异提前加到 v_target 里。 训练好之后，模型一次前向给出的 v_pred 已经天然包含 CFG 效果，推理时只跑一次前向。

公式来源：把 v_guided 当作训练目标 v_target' 反解 v_pred 应该等于什么。 如果训练时让模型直接回归 v_guided，那推理时模型给的就是 v_guided。代数整理后：

训练时 CFG 注入 (training-time) 7.2 \[\begin{aligned} \v_{\text{target}}' \;&=\; \v_{\text{target}} \;+\; \Big(1 - \tfrac{1}{\omega}\Big)\big(\v_c - \v_u\big) \\[4pt] \L_{\text{denoise}} \;&=\; \big\| \v_{\text{pred}} - \v_{\text{target}}' \big\|^2 \end{aligned}\]
推导：记网络看到条件后输出的速度为 $\v_c'$。我们希望 $\v_c' = \v_{\text{guided}} = \v_u + \omega(\v_c - \v_u)$， 即"训练时直接学一个已经被放大的目标"。Pass②（带 grad）的输入是 cond，所以 $\v_{\text{pred}} \approx \v_c'$；把目标改写为 $\v_{\text{target}}'$ 让 MSE 与 $\v_{\text{guided}}$ 对齐。$\omega$ 已被吃进权重，推理只需一次前向。
推导细节
目标是让推理输出 $\v_{\text{pred}} \approx \v_{\text{guided}} = \v_u + \omega(\v_c - \v_u)$。 Pass② 看到的是 cond，所以网络输出记为 $\v_c'$，希望 $\v_c' = \v_{\text{guided}}$。 训练目标改成 $\v_{\text{target}}'$ 使 MSE 把网络推到这个分布： \[ \v_c' \;=\; \v_{\text{target}}' \;=\; \v \;+\; \big(1 - \tfrac{1}{\omega}\big)(\v_c - \v_u) \] 其中 $\v = \x - \eps$ 是真实速度（已知），$\v_c, \v_u$ 来自 Pass③④ 的 stop-grad 前向。推理时 $\omega$ 已被吃进权重里，输出即 $\v_{\text{guided}}$。

7.3 训练时 CFG 的"无条件"分支怎么表达？

ELF 不丢弃 prefix token，而是修改 attention mask： 把条件 prefix 部分的 mask 置 0，让网络看不到它。这样无条件分支与条件分支输入张量形状完全一样， 只是注意力可见性不同，能在同一个 batch 里 batched 跑。 

# codex/elf_pytorch/training.py — uncond/cond 两个 mask 的构造
attn_full  = batch["attention_mask"]            # (B, L+P) 完整 mask
attn_uncond = attn_full.clone()
attn_uncond[:, :cond_prefix_len] = 0            # 屏蔽 source prefix

with torch.no_grad():
    x_hat_u = model(z_t, t, attn=attn_uncond, mode="denoise")
    x_hat_c = model(z_t, t, attn=attn_full,   mode="denoise")
    v_u     = (x_hat_u - z_t) / (1 - t_).clamp(min=1e-3)
    v_c     = (x_hat_c - z_t) / (1 - t_).clamp(min=1e-3)
v_target_cfg = v_target + (1.0 - 1.0 / omega) * (v_c - v_u)
ω 是哪里来的？
训练时 ω 是从一个区间随机采样的（例如 U(1, 3)），并作为 SC-CFG 控制 token 编码进 prefix（§8）。 这样网络可以在不同 ω 下泛化；推理时把目标 ω 编进 prefix 即可。结果是模型学会了一个 ω-参数化的速度场族。
§ 8

控制信号：所有条件都通过 prefix token 注入

DiT 用 adaLN-Zero 把时间、类别条件汇总进 LayerNorm 系数。ELF 选另一条路：把时间、CFG 系数、模式都 编成嵌入向量，拼到序列前面，让 Transformer 通过自注意力读取这些信号。

§ 10

优化：Muon + AdamW，分开处理矩阵与向量参数

Muon (Jordan et al. 2024) 是 2024 年提出的二阶启发式优化器，在矩阵参数上比 Adam 收敛更快。 ELF 用 Muon 优化 2D 权重矩阵，AdamW 优化 1D 参数（bias, norm γ, embedding）。

10.1 直觉：让更新方向"正交化"

Adam 的更新方向是 m / (√v + ε)，本质是把每个坐标独立缩放。 但神经网络的权重矩阵有结构——奇异值分布通常很不均匀，少数大方向支配更新。 Muon 通过Newton-Schulz 迭代近似把更新方向 G 投影到正交矩阵流形， 让所有方向上的步长更均衡，等效于在 G 的 SVD 上把奇异值都拍平到 1。

Muon 单步更新 10.1 \[\begin{aligned} G_t \;&=\; \mu \cdot G_{t-1} \;+\; \nabla_W \L \\[2pt] O_t \;&=\; \mathrm{NewtonSchulz}_5(G_t) \;\approx\; U V^{\top}, \text{ where } G_t = U \Sigma V^{\top} \\[2pt] W_t \;&\leftarrow\; W_{t-1} \;-\; \eta \cdot O_t \end{aligned}\]
$G_t$ 是动量加权梯度；$O_t$ 是它的"正交化"近似——把 SVD 中的奇异值都拍平到 1。 等价于让所有方向用同样的步长，不被支配方向"吞掉"次要方向。

10.2 Newton-Schulz 迭代

$\mathrm{NewtonSchulz}(G)$ 是 5 步迭代，每步是一个三次多项式作用：

Newton-Schulz 单步 10.2 \[ P(X) \;=\; a\,X \;+\; b\,(X X^{\top}) X \;+\; c\,(X X^{\top})^2 X \]
Muon 论文给的常数 $(a, b, c) = (3.4445,\;-4.7750,\;2.0315)$；初始化 $X_0 = G / \|G\|_F$，重复 $X_{k+1} = P(X_k)$ 五次。 每步把 $X$ 的奇异值 $\sigma$ 沿 $p(\sigma) = a\sigma + b\sigma^3 + c\sigma^5$ 推向 1，5 次后基本收敛。

10.3 哪些参数用 Muon？

参数类型形状优化器原因
attention QKV、Out2DMuon典型矩阵参数，能受益于正交化
FFN W_g / W_u / W_d2DMuon同上
RMSNorm γ1DAdamW向量参数，无 SVD 结构
bias1DAdamW同上
token / mode embedding2D 但稀疏AdamW每步只激活少量行，正交化没意义

DDP 下的正确性
Muon 的更新方向不是逐坐标线性运算，all-reduce 之后再做 NS 跟先做 NS 再 reduce 不等价。 解决：每个 rank 先 all-reduce 梯度（用 fp32 全精度，保证 bit-identical），然后所有 rank 各自跑 NS。 只要梯度一致，5 步 NS 的输出就一致。这要求 Muon 优化的参数在所有 rank 上参数完全同步——DDP 默认保证。
§ 11

采样：用 Euler 法沿 ODE 走 N 步

训练完成后，生成就是解 ODE：dz/dt = v_pred(z, t)，z(0) = ε。最简单的 Euler 法把 [0, 1] 切 N 段，每段走一小步。 ELF 默认 N=16，质量已经接近 N=64。 

# codex/elf_pytorch/sampling.py — Euler ODE 采样核心
def sample(model, shape, cond, omega=2.0, n_steps=16):
    z     = torch.randn(shape, device=device)               # z_0 ∼ 𝒩(0, I)
    prev  = torch.zeros_like(z)                            # 自条件初值
    dt    = 1.0 / n_steps
    for i in range(n_steps):
        t     = torch.full((shape[0],), i * dt, device=device)
        x_hat = model(z, t, prev=prev, cond=cond, omega=omega, mode="denoise")
        v     = (x_hat - z) / max(1 - i * dt, 1e-3)         # x-pred → v-pred
        z     = z + dt * v                                  # Euler step
        prev  = x_hat.detach()                                # 自条件喂回下一步

    # 最后一次 forward 切到 decode mode → tokens
    x_final = model(z, t=torch.ones_like(t), cond=cond, mode="decode")
    tokens  = model.unembed(x_final).argmax(-1)
    return tokens
为什么不用更高阶 ODE？
Heun, RK4 在每步多调用 1-3 次前向，开销翻倍。对 ELF 而言，自条件已经吸收了大部分误差累积， Euler 在 N=16 时质量已经接近饱和。如果显存允许，把 N 增大比换求解器划算。
§ 12

8×H200 工程：DDP · grad accum · bf16

H200 单卡 141 GB HBM，跑 ELF-L 也能保持每卡 micro-batch 4。 真正的瓶颈不是显存，而是 DDP 同步频率、bf16 数值稳定性、梯度累积下的 EMA / branch 同步。

12.1 关键工程量

规模micro-bsgrad accumglobal batch大致 step time显存峰值
ELF-B (105M)164512~0.9 s~40 GB
ELF-M (342M)88512~1.6 s~70 GB
ELF-L (652M)416512~2.8 s~110 GB

step time 含 4 次 denoiser forward + 1 次 backward；序列长度 L=256, T5 d=512。

12.2 bf16 的取舍

ELF 训练用 bf16 forward + bf16 backward + fp32 master weights + fp32 grads 的混合精度。 理由：

  • bf16 forward/backward：H200 的 Tensor Core 在 bf16 下吞吐 ≈ fp16 / fp32 的 2× / 4×。
  • fp32 grads：Muon 的 Newton-Schulz 是非线性矩阵运算，bf16 会让奇异值估计偏。 在 backward 之后立刻把 grad 累积到 fp32 buffer，再做 all-reduce。
  • fp32 master weights：每个 optimizer step 后把 bf16 副本从 fp32 master 同步出来。
为什么不用 fp16？
fp16 动态范围窄（±65504），训练扩散模型时 v_target 偶尔会有较大值，容易溢出。 bf16 跟 fp32 同范围（指数位 8 bit），代价是精度位少（7 bit），但 ELF 用 RMSNorm + QK-Norm 把内部数值"压"得很稳，bf16 精度足够。
