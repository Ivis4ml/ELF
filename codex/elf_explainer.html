Embedded Language Flows

ELF：把语言生成放进连续嵌入空间里的 Flow Matching

这个页面解释 `codex/` 里的 PyTorch 版本做了什么：冻结 T5 encoder 得到连续 token 表示， 用一个共享权重的 Transformer 同时学习去噪和最终离散化，并面向 8xH200 做 DDP 训练。

ELF PyTorch
核心想法 训练目标 实现结构 8xH200 运行入口

核心想法：大部分时间保持连续，最后一步才回到 token

传统语言模型直接预测离散 token。ELF 先把 token 序列编码成连续嵌入 `x`， 从高斯噪声 `z0` 逐步流向干净嵌入 `x`，只在 `t=1` 时使用 unembedding 得到词表 logits。

1

Tokenize

输入文本变成 token id，条件任务会把 source prefix 接到 target 前面。

2

Encode

冻结 T5 encoder 输出上下文化嵌入，并按 latent mean/std 归一化。

3

Flow

用线性插值构造 `zt = t*x + (1-t)*eps`，学习从噪声到数据的速度场。

4

Denoise

ELF Transformer 预测干净嵌入 `x_pred`，再换算成 velocity 做 MSE。

5

Decode

`t=1` 分支共享同一网络，接 unembedding 后用 CE 学会回到离散 token。

采样时，ELF 从高斯噪声开始，逐步把连续嵌入修正成可解码的语言表示。
Why Continuous

为什么这样有效

  • 连续空间天然适合 Flow Matching、ODE/SDE sampler 和 CFG。
  • 上下文化 T5 嵌入让每个位置已经带有句子级语义。
  • 最终离散化只发生一次，避免每个去噪步都被词表分类目标绑住。
  • 共享 denoiser/decoder 权重，不需要额外训练一个独立 decoder。

训练由两个分支交替组成

源码和论文默认 80% denoiser 分支、20% decoder 分支。PyTorch 版保持这个 step-level branch sampling， 每个 micro-step 随机选择一个目标来训练同一个 ELF 网络。

Denoiser branch

学习连续流

采样时间 `t`，把干净嵌入 `x` 和高斯噪声 `eps` 插值得到 `zt`。 网络输出 `x_pred`，再换算成 velocity 和目标速度比较。

zt = t*x + (1-t)*eps
v_pred = (x_pred - zt) / max(1-t, eps_t)
loss = mean((v_pred - v_target)^2)
Decoder branch

学习最终离散化

在 `t=1` 时输入已经接近干净嵌入，所以训练时额外按 token 级别加噪。 同一个 ELF 网络进入 decode mode，输出经 unembedding 做 cross entropy。

z_decode = p*x + (1-p)*eps
h = ELF(z_decode, t=1, mode=decode)
loss = CE(unembed(h), tokens)

条件、CFG 和自条件都通过上下文 token 注入

ELF 不用 adaLN-Zero 汇总所有控制信号，而是把时间、self-conditioning CFG scale、mode token 作为 prefix token 拼到序列前面，让 Transformer 通过自注意力读取这些控制信号。

`codex/` 里的实现结构

这版是独立 PyTorch 栈：使用 Hugging Face `T5EncoderModel` 作为冻结 encoder， 用 DDP/NCCL 在 H200 上训练 ELF 主体。

elf_pytorch/model.py ELF Transformer、RoPE、RMSNorm、SwiGLU、decoder head。
elf_pytorch/training.py denoiser/decoder loss、自条件、training-time CFG。
elf_pytorch/train.py DDP 训练循环、bf16、EMA、checkpoint、日志。
elf_pytorch/optim.py Muon 和 AdamW 参数分组。
elf_pytorch/data.py HF dataset、collate、条件 prefix attention mask。
elf_pytorch/sampling.py ODE/SDE 风格采样工具。
configs/*.yaml ELF-B/M/L 的 8xH200 配置。
train.py 仓库根目录安全入口，避开顶层 `torch/` 目录冲突。

8xH200 训练配置的关键点

H200 显存很宽裕，但 1024 长度、全注意力、T5 encoder 和 ELF-L 仍然需要合理的 micro-batch 与梯度累积。 当前配置保持 effective global batch 为 512，以对齐论文和原始配置。

ELF-B

105M

每卡 micro-batch 16，累积 4 步，适合先做完整链路验证。

ELF-M

342M

每卡 micro-batch 8，累积 8 步，吞吐和显存更稳。

ELF-L

652M

每卡 micro-batch 4，累积 16 步，建议先跑短步数 smoke train。

论文中的系统级比较显示 ELF 在较少采样步数下有较强生成质量；本 PyTorch 版目标是复现训练路径，而不是引入额外架构改动。

最短运行路径

训练入口在 `codex/train.py`。从仓库根目录启动时，Python 会优先使用真实 PyTorch 包， 不会把仓库的顶层 `torch/` 文件夹误当成依赖。 

pip install -r codex/requirements-pytorch.txt

cd codex
PYTHONPATH=. pytest tests/test_smoke.py
cd ..

torchrun --standalone --nproc_per_node=8 \
  codex/train.py \
  --config codex/configs/train_owt_elf_b_8xh200.yaml
建议顺序：先在 CPU 或单卡上跑 smoke test，再在 8xH200 上用 ELF-B 配置跑几十个 step； 确认 loss、显存和 checkpoint 都正常后，再切到 ELF-M 或 ELF-L。
